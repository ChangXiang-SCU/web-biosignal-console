多模态生理信号同步采集系统

Polar H10 心电 + 天琴座 Lyra 皮肤电 + Arduino GSR

技术说明与论文方法学写作材料 · 2026-09-04

这份文档回答一个问题：这套系统到底测了什么、怎么测的、写论文时该怎么如实汇报。文中所有采样率、延迟、参数都是在这台机器上实测得到的，不是抄标称值；凡是推测或未经验证的地方都单独标注。

一、系统概览

三台互相独立的传感器，通过一个网页（polarconsole_eda.html）同时采集，全部对齐到同一根时间轴上，各自导出 CSV。网页只用浏览器原生能力：心电和皮肤电走 Web Bluetooth，串口 GSR 走 Web Serial，不需要安装任何软件或驱动。

| **通道** | **设备**                    | **测量量**             | **实测采样率** | **传输**          |
|----------|-----------------------------|------------------------|----------------|-------------------|
| ECG      | Polar H10 胸带              | 单导联心电（µV）       | 129.4–129.9 Hz | BLE / Polar PMD   |
| ACC      | Polar H10 胸带              | 三轴加速度             | 约 202.6 Hz    | BLE / Polar PMD   |
| EDA      | 天琴座 Lyra（Nervous EDA）  | 16 频点复阻抗谱        | 8.001 Hz       | BLE / Nordic UART |
| GSR      | Arduino UNO + 模拟 GSR 模块 | 单点皮肤电导（未校准） | 10.00 Hz       | USB 串口 / CH340  |

> *三台设备各有各的时钟，彼此不同步，也都不等于电脑的时钟。所有跨模态分析必须使用 CSV 里的 unix_host_ms 列，不要用 unix_dev_ms（详见第五章）。*

二、Polar H10 · 心电

2.1 原理

胸带上两个干电极贴在胸前，测量心脏去极化在体表产生的电位差，即单导联心电图。数据经 Polar 私有的 PMD（Polar Measurement Data）BLE 服务传出，是未滤波的单导联电压，单位 µV（Polar Measurement Data Specification：ECG 帧类型 0，3 字节/样本，单位 µV）。

2.2 实测参数

| **项目**   | **值**                               | **说明**                       |
|------------|--------------------------------------|--------------------------------|
| 标称采样率 | 130 Hz                               | Polar 官方文档                 |
| 实测采样率 | 129.42–129.87 Hz                     | 由包间隔与包内样本数反算       |
| 每包样本数 | 73                                   | ECG 流                         |
| 分辨率     | 14 bit，3 字节/样本，小端有符号      |                                |
| 单位       | µV                                   | Polar PMD 规范给出             |
| 服务 UUID  | fb005c80-02e7-f387-1cad-8acd2d8df0c8 | PMD Service                    |
| R 波检出   | 平均 +3 SD 阈值 + 300 ms 不应期      | 本文分析脚本所用，非采集端处理 |

> *包边界时间戳修正：Polar 设备实际 ODR 未必等于标称值。本系统用相邻两包设备时间戳之差除以包内样本数得到真实采样间隔，首包或断流后回退标称值。实测 H10 加速度计每包 36 样本、设备时间戳只前进 177.65 ms（真实 4.935 ms/样本 ≈ 202.6 Hz，而非标称 5 ms/200 Hz）；写死标称值会让时间轴累计走快约 1.3%。*

三、天琴座 Lyra 皮肤电 · 这台设备到底是什么

3.1 真实身份与可引用文献

这台设备在淘宝以「天琴座 Lyra 皮肤电传感器」售卖，但它的固件在 BLE 设备信息服务里自报的厂商是 “INL - INSA Lyon”、型号是 “Nervous EDA Sensors”。它是法国 INSA Lyon / CNRS / 里昂纳米技术研究所（INL UMR 5270）开源硬件项目 Nervous Toolkit 中 EDA 传感器的贴牌产品，MIT 协议，仓库为 sensors-inl/Nervous-EDA。

论文里不应只写商品名——贴牌商品名不可引用。应当引用原始设计的论文：

> B. Massot, E. Desmazure, A. Montalibet, E. McAdams, and C. Gehin,
>
> "A Portable Device Performing Continuous Impedance Spectroscopy
>
> for Skin Conductivity," IEEE Sensors Journal, 2024.
>
> DOI: 10.1109/JSEN.2024.3485187

该项目由法国国家科研署（ANR）资助，项目号 ANR-22-CE31-0023-03（RENFORCE）。硬件由两颗芯片构成：Infineon PSoC Analog Coprocessor 负责信号产生与调理，Insight SiP ISP1807（内含 Nordic nRF52840）负责采样、阻抗计算与 BLE 通讯。原设计为腕戴式。

> *原始设计是腕戴（wrist-worn）。腕部汗腺密度远低于掌侧，是公认信噪比较差的 EDA 测量位点。如果你把它当掌侧电极用，或反过来按腕戴用却期待掌侧的信号幅度，都需要在论文里说明位点，并注意与文献可比性。*

3.2 测量原理（这是和普通 GSR 最本质的区别）

普通 GSR 模块给皮肤加一个直流电压，测流过的电流，得到一个数——单一的直流电导。这台设备完全不同：它同时向皮肤注入 16 个不同频率的微小交流电流，同步采集电压和电流波形，对采到的波形做 FFT，在每个频率上分别解出复导纳（电导 + 电纳），也就是一条完整的阻抗谱。

这么做的价值在于，皮肤不是纯电阻。角质层像电容，汗腺导管像电阻，二者并联。直流只能看到一个混合结果；多频扫描可以把这两部分分开——低频主要反映汗腺活动（真正的 EDA 信号），高频主要反映角质层电容。这也是为什么设备用 12 Hz 那一路来算电导：频率最低、对汗腺最敏感。

16 个频率（Hz）

> 12, 28, 32, 36, 44, 68, 84, 108, 136, 196, 256, 324, 400, 484, 576, 724

每 125 ms 输出一整条 16 点的谱，即 8 条谱/秒。每条谱在复平面上画出来就是一张 Nyquist 图，理想情况下 16 个点落在一段圆弧上（Cole 模型），拟合这段圆弧得到的圆心和半径就是皮肤等效 RC 网络的特征参数。

> *注入电流的具体幅度、激励波形、FFT 窗长这几个参数，厂商文档和开源仓库的 README 都没有公开，需要读固件源码或原论文才能确定。论文里如果要写电流大小，必须查证后再写，不能编。*

3.4 通讯协议

设备不使用任何加密。它跑的是 Nordic UART Service（NUS），一个厂商自定义的 BLE 透传服务。Windows 蓝牙面板只认标准 Profile，所以在系统里能看到设备却配不上，这不是加密导致的。

|-----------|---------------------------------------------------------------------|
| BLE 服务  | 6E400001-B5A3-F393-E0A9-E50E24DCCA9E（NUS）                         |
| 设备→主机 | 6E400003-…（notify）                                                |
| 主机→设备 | 6E400002-…（write）                                                 |
| 成帧      | COBS，0x00 作帧分隔符                                               |
| 序列化    | Protocol Buffers（proto3）                                          |
| 消息      | EdaBuffer { repeated Impedance data = 1; Timestamp timestamp = 2; } |
|           | Impedance { float real = 1; float imag = 2; }                       |
|           | Timestamp { uint64 time = 1; uint32 us = 2; }                       |
| 广播名    | SichirayEDA_XXXX（官方文档写的 Sichiray_XXXX 与实机不符）           |

> *实测该设备的 RTC 会漂移（曾测得比电脑快约 60 秒），本系统每次连接自动对表。厂商自带上位机的对表功能因为 COBS 帧多了一个前导 0x00 而被固件拒收，实际从未生效。*

3.5 已知的设备固有伪迹：两相交织

12 Hz 电导逐样本在两个值之间跳变。这不是电极接触问题——把电极接到人身上、阻抗从 77 kΩ 降到 28 kΩ 之后，交替依旧。逐频点计算一阶自相关（lag-1）可以看清来源：

> 28 Hz -0.647 108 Hz -0.478 196 Hz +0.021
>
> 32 Hz -0.819 136 Hz -0.175 256 Hz +0.049
>
> 36 Hz -0.814 12 Hz -0.214 324 Hz +0.019
>
> 44 Hz -0.934 68 Hz -0.803 400 Hz +0.019

28–108 Hz 一段的 lag-1 逼近 −1，这是两相交织的典型特征：设备在两组激励条件之间轮流测量，同一频点相邻两帧来自不同的测量条件。

正确的处理是长度 2 的滑动平均，它的频率响应在 Nyquist 频率（即交替分量所在处）恰好为零点，可以精确抵消该分量。实测对比（30 秒真人数据）：

| **处理**           | **标准差** | **lag-1** | **评价**                   |
|--------------------|------------|-----------|----------------------------|
| 原始 8 Hz          | 8.84       | −0.358    | 有交替                     |
| 抽取偶数帧（4 Hz） | 8.43       | +0.841    | 可行但丢一半数据           |
| 抽取奇数帧（4 Hz） | 9.13       | +0.509    | 同上                       |
| 长度 2 滑动平均    | 5.02       | +0.742    | 采用                       |
| 3 点中值           | 6.60       | −0.520    | 更糟，中值处理不了两相交织 |

> *论文里必须报告这一步。写法建议：「原始 8 Hz 电导序列存在设备固有的逐样本两相交替（28–108 Hz 各频点 lag-1 自相关约 −0.5 至 −0.9），采用长度为 2 的滑动平均消除该分量后再做后续分解；未经处理的原始序列同时保留于 EDA_G_raw 列。」*

四、Arduino 模拟 GSR

4.1 构成与原理

这是完全不同的一套东西：一块模拟 GSR 模块（Grove GSR 同类），输出一路模拟电压到 Arduino UNO 的 A0，单片机读 ADC 后从 USB 串口打出来。模块内部是一个运放电路，把两指之间的电阻变化转换成电压。它只有一个直流工作点，没有频率信息。

4.2 实测参数

| **项目** | **值**                                   | **说明**                                        |
|----------|------------------------------------------|-------------------------------------------------|
| 板卡     | ATmega328（UNO/Nano 兼容）               | 复位后 STK500 bootloader @115200 应答 0x14 0x10 |
| 输出速率 | 10.00 Hz                                 | millis 间隔恒定 100 ms，零抖动                  |
| 积分窗口 | 100 ms 内连续过采样求平均                | 见下                                            |
| ADC      | 10 bit（0–1023）                         | A0                                              |
| 串口     | 115200 8N1，每行 "millis,adc"            |                                                 |
| 固件     | GSR_serial.ino，占 2056 字节（6% flash） |                                                 |

为什么积分窗口是 100 ms

第一版固件用 20 Hz 输出、每点内部平均 10 次（跨度约 3 ms）。实测读数在 0 和 137 之间逐样本硬跳。原因是 3 ms 的平均窗口远小于工频周期，平均值直接跟随市电相位，20 Hz 采样又恰好把工频混叠成逐样本交替。

改为在整个 100 ms 窗口内连续过采样再平均：100 ms 正好是 50 Hz 的 5 个周期、60 Hz 的 6 个周期，两种电网都能整周期积分抵消工频串扰。重烧后 ADC 从 0–140 的乱跳变为 54–60 的稳定读数（std 0.38）。

> *这一条对任何模拟生理传感器都成立，值得写进论文的方法学：模拟通道的采样窗口应取工频周期的整数倍。100 ms 是同时兼容 50 Hz 和 60 Hz 的最小公倍周期。*

4.3 换算与极性（重要，必须在论文里声明）

常见的 Grove GSR 换算式为：

> R_human(Ω) = ((1024 + 2·ADC) × 10000) / (512 − ADC) G(µS) = 1e6 / R

该式把 ADC 上升解释为电阻上升、电导下降。但在 2026-09-04 的心算应激实验中实测到相反的方向：标记后 ADC 从 165 升到 238（+44%），同一时间由 ECG 独立算出的心率从 69.3 升到 72.6 bpm，两者 30 秒分箱相关 r = +0.674。也就是说，在这块模块上「ADC 上升 = 唤醒上升 = 电导上升」，与该公式的极性相反。

系统因此提供极性开关，默认使用中点镜像 v′ = 511 − ADC 后再套原式（既翻转方向又保持在公式定义域内）。

> *这块模块没有经过任何校准，µS 的绝对值不具备计量意义，只能作为相对唤醒指标使用。论文中报告时应优先使用 GSR_raw（原始 ADC），或明确声明所用换算式与极性约定；不要把这里的 µS 与文献中经过校准的 SCL 数值直接比较。*

五、时间同步

5.1 问题

三台设备各有独立时钟。实测发现 Polar H10 的内部 RTC 从未被对过表，写出的绝对时间是 2019 年，与天琴座（真实 POSIX 时间）相差 7.7 年；Arduino 只有开机以来的 millis，没有绝对时间概念。因此设备自报的时间戳之间无法直接比较。

5.2 方案

系统对每台设备记录首包的设备时刻与该包到达浏览器的墙钟时刻，用这个锚点把设备时钟平移到主机时钟：

> hostOffset(dev) = systemStartUTC\[dev\] − (starttime\[dev\] + EPOCH_2000_TO_1970)
>
> unix_host_ms = dev_ms + EPOCH_2000_TO_1970 + hostOffset(dev)

验证：构造一台时钟停在 2019 年的模拟设备与一台时钟正确的模拟设备，两者 unix_dev_ms 相差 242 202 968 秒，而 unix_host_ms 相差 0 ms，均等于真实墙钟。

5.3 残余误差

| **来源**                 | **量级**                                 | **是否可校正**                      |
|--------------------------|------------------------------------------|-------------------------------------|
| BLE 传输延迟（常数项）   | 天琴座中位 221 ms                        | 可用 CSV 顶部 SYNC 表的 offset 校正 |
| 延迟抖动                 | 中位 15.8 ms（正常）/ 614 ms（BLE 拥塞） | 不可，但可用于剔除拥塞时段          |
| 设备时钟频率偏差（skew） | 约 1e−4 量级                             | SYNC 表给出 skew，可做线性校正      |
| 串口积压                 | 曾达 19 s（已修复）                      | 已在采集端消除                      |

> *每份 CSV 顶部都写有 SYNC summary（每台设备每条流的 offset、skew、延迟中位数、抖动；只基于最近 300 包）；Polar_auto_\* 增量文件和手动导出的 RAW 文件另有 SYNC per-packet（逐包到达差，每个分组文件只带自己那一路），全部 auto 文件拼起来就是全程逐包记录，要全程拟合 skew 用它。做严格的跨模态时序分析（例如 SCR 与 R 波的时间关系）时应使用这些参数做二次校正，而不是只用 unix_host_ms。*

六、信号处理链与 CSV 字段字典

6.1 天琴座 EDA 处理链

> 复阻抗(16 频点) → 取 12 Hz → \|Z\| = √(re²+im²) → G = 1e6/\|Z\| \[µS\]
>
> → 2 点滑动平均去交替 → EDA_G
>
> → 一阶指数平滑 α=0.04 → EDA_SCL（tonic）
>
> → EDA_SCR = EDA_G − EDA_SCL（phasic）
>
> → 峰检测：局部极大 ∧ 幅度≥0.02 µS ∧ 峰间隔≥2.0 s

指数平滑的时间常数 τ = 1/(α·fs) = 1/(0.04×8) ≈ 3.1 秒。这三个参数（α、峰阈值、最小峰间隔）沿用厂商上位机的取值，以保证与厂商软件的输出可比；如果论文需要，可以改用 cvxEDA、Ledalab 等标准分解方法重新处理原始 EDA_G。

7.1 心算应激诱发实验（2026-09-04 03:05）

三路同步录制约 10 分钟，在 03:05:35 打标记后开始连续减 17 的心算任务。30 秒分箱，标记前 4 箱与标记后 11 箱对比：

| 心率（H10 ECG） | 69.3       | 72.6       | +3.3 bpm | —                | +0.744           |

Arduino GSR 与由 ECG 独立算出的心率在 30 秒尺度上相关 r = +0.674。两条互不相干的生理通路同向变化，构成应激反应真实存在的证据，该通道可用。

天琴座在同一刺激下没有任何可检测的反应（与心率相关 −0.19，等同于无）。解码链路已独立验证无误，因此问题定位在硬件本体、电极或佩戴方式，而非软件。

> *结论：截至本文档写作时，我们手上这一台天琴座尚未通过生理有效性验证。在原因查明之前，本项目的皮肤电数据以 Arduino GSR 通道为准。以上为单台设备的实测记录，样本量为 1，不足以推断该型号的普遍表现；换一台或升级固件后应重新验证。*

八、必须在论文里声明的局限

- 天琴座通道未通过应激诱发验证（第 7.1 节）。在问题定位并复测通过前，不应报告其数据。

- Arduino GSR 未经校准，µS 绝对值无计量意义；应报告原始 ADC 或明确声明换算式与极性约定。

- Grove 换算式的极性在本模块上与常见文献相反，系由实验数据判定，非厂商说明。

- Polar H10 输出单位为 µV（按 Polar PMD 规范），信号未滤波；干电极胸带的幅度与临床湿电极导联不可直接比较。

- 天琴座存在设备固有的两相交织伪迹，已用长度 2 滑动平均处理，须在方法中报告。

- BLE 传输引入约 221 ms 的常数延迟，跨模态时序分析需用 SYNC 表校正。

- BLE 拥塞时（三路同时高速传输）曾出现天琴座断流 2.8 分钟、抖动升至 614 ms。建议不需要时关闭 ACC 通道（200 Hz，占用空口最多）。

- 注入电流幅度、激励波形、FFT 窗长等参数未公开，如需在论文中报告须查证原始固件或论文。

- 天琴座原始设计为腕戴式；测量位点会显著影响 EDA 幅度与信噪比，须在论文中说明实际位点。
