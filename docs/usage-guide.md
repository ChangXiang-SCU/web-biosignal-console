皮肤电 + 心电 同步采集台

使用说明 · v1.2 · 2026-09-06

这是一个单文件网页，用浏览器原生能力同时采集 Polar H10 心电、串口 GSR 皮肤电，并把三路对齐到同一根时间轴上导出 CSV。不需要安装任何软件、驱动或 Python 环境。

一、需要什么

|        | **设备**                         | **说明**                                                  |
|--------|----------------------------------|-----------------------------------------------------------|
| 浏览器 | Chrome 或 Edge                   | 必须。Safari / Firefox 不支持 Web Bluetooth 与 Web Serial |
| 心电   | Polar H10 胸带                   | 可选。走蓝牙，无需配对                                    |
| 皮肤电 | Arduino UNO/Nano + 模拟 GSR 模块 | 走 USB 串口。板子需先烧 GSR_serial.ino                    |
| 电极   | GSR 指套                         | 贴手掌侧，食指与中指的中节指腹                            |

二、Arduino 接线与烧录

接线（模块背面有丝印）：

> GND → GND 5V → 5V OUT → A0

用 Arduino IDE 打开 GSR_serial.ino，开发板选 Arduino Uno，端口选板子对应的 COM 口，点上传。烧好后打开串口监视器（115200），应该看到每秒 10 行，形如：

> 12500,28.417
>
> 12600,28.392
>
> *如果输出没有小数点，说明烧的是旧版固件。带小数是 v1.2 的标志 —— 它靠 100 ms 窗口内的过采样把有效分辨率从 0.05 µS 提到约 0.003 µS。*

三、采集步骤

1.  用 Chrome 打开 polarconsole_eda.html（直接双击即可，不用架服务器）

2.  先在右侧「输出」里点「选择输出文件夹」。不选的话数据只在内存里，刷新就没了

3.  点「连接皮肤电 · 串口 GSR」，在弹窗里选 Arduino 那个 COM 口

4.  要采心电就再点「连接传感器」，选 Polar H10

5.  戴好电极后静置 2 到 5 分钟，等接触阻抗稳定

6.  点「开始录制」。要打事件标记就在右下角输入名字、点「添加」生成按钮，事件发生时点它

7.  结束点「停止录制」

> *录制期间把这个标签页保持在前台。切到后台浏览器会限流，蓝牙链路可能断（会自动重连，但数据会有缺口）。*

四、输出文件

输出文件夹里会出现两类文件。auto 是每 60 秒写一次的增量片段，full 是停止录制时写出的完整合并文件。做分析用 full。

| **文件**     | **内容**                                             |
|--------------|------------------------------------------------------|
| \*\_GSR.csv  | GSR_raw（原始 ADC）、GSR_uS（电导）、GSR_ohm（电阻） |
| \*\_ECG.csv  | Polar 心电原始 ADC，130 Hz                           |
| \*\_ACC.csv  | 三轴加速度，约 200 Hz                                |
| \*\_EDA.csv  | 天琴座处理后信号（见第六节）                         |
| \*\_EDAZ.csv | 天琴座 16 频点原始复阻抗，32 列                      |

CSV 的结构

每份 CSV 顶部有三段元信息，之后才是数据表头（以 DevTime_us 开头的那一行）：

- MARKERS：事件标记，时刻用的是统一时间轴，可直接与数据行对齐

- LINK EVENTS：蓝牙掉线与重连事件，数据缺口的成因记录

- SYNC：每台设备每条流的时钟偏移、频率偏差、传输延迟与抖动

三个时间列

| **列**       | **用途**                                           |
|--------------|----------------------------------------------------|
| unix_host_ms | 统一主机时间轴。跨设备分析一律用这一列             |
| unix_dev_ms  | 设备自报的时间。各设备时钟互不相干，不可跨设备比较 |
| DevTime_us   | 设备时钟的原始微秒值                               |

> *Polar H10 的内部时钟往往从未对过表（实测写出来是 2019 年）。所以跨模态对齐必须用 unix_host_ms，不要用 unix_dev_ms。*

五、分析入口

CSV 前 4 行是元信息，读的时候跳过即可：

> import pandas as pd, neurokit2 as nk
>
> df = pd.read_csv("...\_GSR.csv", skiprows=4)
>
> sig = df\["GSR_uS"\].dropna().values
>
> signals, info = nk.eda_process(sig, sampling_rate=10)

会得到 EDA_Tonic（SCL）、EDA_Phasic（SCR）与 SCR_Peaks。10 Hz 对皮肤电绰绰有余：SCR 上升时间 1 到 3 秒，信号能量在 1 Hz 以下，Empatica E4 只有 4 Hz。

> *GSR 模块未经校准，µS 的绝对值没有计量意义，不能跨被试比较。做被试内归一化（每人 z-score），或直接用 GSR_raw。*

六、天琴座 Lyra 通道的现状

这套系统也集成了天琴座 Lyra 皮肤电传感器（BLE，16 频点阻抗谱，8 Hz），协议已完整实现、解析零错误。但在**我们手上这一台**（固件 1.0.0）上，2026-09-06 的验证没有通过，暂未用于正式实验。以下是实测记录，不代表该型号的普遍表现：

- 心算应激实验中对刺激无反应（与同时记录的心率相关 −0.19），而同一时刻的 GSR 通道相关 +0.674

- 16 频点阻抗不随频率单调下降，反而在高频升高。真实皮肤是并联 RC，这个谱型物理上不可能

- 接触质量指标 EDA_Cfit 中位 0.27（合格应低于 0.10），左右手对调后无改善

- NeuroKit2 算出的 SCR 平均幅度 93 µS，真实 SCR 在 0.01 到 1 µS 之间

在该设备问题解决之前，皮肤电数据请以串口 GSR 通道为准。天琴座相关的列仍照常导出，不影响其他通道。

七、常见问题

| **现象**                      | **原因与处理**                                                                            |
|-------------------------------|-------------------------------------------------------------------------------------------|
| 串口连不上 / 烧录失败         | 网页占着 COM 口。关掉标签页再试                                                           |
| 串口读数在 0 和一两百之间乱跳 | GSR 模块没接到 A0，或指套没戴。悬空引脚在吃工频                                           |
| 蓝牙搜不到设备                | Chrome 的蓝牙选择器是系统弹窗，需要手动点设备名。另确认设备已开机                         |
| 录着录着蓝牙断了              | 会自动重连（最多 20 次），缺口记在 LINK EVENTS 段。频繁掉线可关掉 ACC 流，200 Hz 最占空口 |
| Excel 打开表头很怪            | 前 4 行是元信息段，数据表头在第 5 行                                                      |
| 数据只在内存里                | 忘了选输出文件夹。选了才会每 60 秒落盘                                                    |
